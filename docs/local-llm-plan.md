# 로컬 LLM 앱 계획 (검토용 초안)

Ollama처럼 오픈소스 모델을 받아 내 PC에서 돌리는 앱입니다. 모델 파일만 Hugging Face에서 받고, 나머지는 전부 직접 만듭니다. 추론 엔진, 토크나이저, 모델 받기, API 서버, 화면이 여기에 들어갑니다. llama.cpp, Ollama, ONNX Runtime 같은 기존 엔진은 앱에 넣지 않습니다.

이 문서는 아직 계획입니다. 1절의 결정을 정해 주시면 그에 맞춰 고친 뒤 0단계부터 시작합니다.

## 2. 이 PC에서 확인한 것

계획 전에 Electron 45로 짧게 실험했습니다. 실험 파일은 지웠습니다.

- 사양: Ryzen 7 4800H(8코어), RAM 31GB, GTX 1650 4GB와 AMD 내장 GPU, C 드라이브 여유 59GB. C/C++ 컴파일러는 없습니다(nvcc는 있지만 cl.exe가 없어 못 씁니다).
- WebGPU는 됩니다. 단, 그냥 켜면 내장 AMD GPU가 잡힙니다(f16 행렬·벡터 곱 6GB/s). `force_high_performance_gpu` 스위치를 주면 GTX 1650(turing)이 잡히고, 같은 곱이 69GB/s로 빨라졌습니다(측정, 2048x2048 f16 한 개, 단순한 셰이더).
- 한 버퍼의 최대 크기는 2GB입니다. 모델은 텐서마다 버퍼를 따로 만들기 때문에 문제가 되지 않습니다.
- `shader-f16`을 지원합니다.
- Hugging Face API로 GGUF 저장소 검색, 파일 목록, 파일 크기, sha256이 받아집니다. 예: Qwen2.5-1.5B-Instruct Q4_K_M은 1.12GB입니다.

속도 예상(추정): 토큰 하나를 만들 때 가중치를 한 번 다 읽습니다. 1.5B Q4_K_M(약 1.1GB)을 70~100GB/s로 읽으면 이론상 초당 60~90토큰이 한계입니다. 실제로는 그 절반 정도인 초당 25~40토큰을 첫 목표로 잡습니다. 0단계에서 실제 숫자로 바꿉니다.

## 3. 범위

**직접 만드는 것**
- GGUF 파일 읽기(메타데이터, 텐서 목록, 양자화 블록)
- WebGPU 연산: 양자화된 행렬 곱, RMSNorm, RoPE, 어텐션, SwiGLU, softmax, 샘플링
- 모델 구조: Llama 계열(llama, qwen2, qwen3)
- 토크나이저: GGUF에 든 어휘로 BPE(GPT-2 바이트 방식)와 SentencePiece 방식, 모델별 사전 분리 규칙(`tokenizer.ggml.pre`)
- 채팅 템플릿: GGUF의 `tokenizer.chat_template`(Jinja)을 실행하는 작은 해석기
- KV 캐시, 대화 이어 쓰기, 중단, 스트리밍
- CPU 대체 경로(JavaScript, 작은 모델과 GPU가 없는 PC용, 느림)
- 모델 검색, 받기(이어받기, sha256 확인), 삭제, 모델별 설정(시스템 프롬프트, 온도, 문맥 길이)
- 로컬 API 서버: Ollama 호환과 OpenAI 호환
- 화면: 채팅, 모델 관리, 설정

**가져오는 것**
- 모델 가중치 파일(GGUF)만 Hugging Face에서 받습니다. 모델마다 라이선스를 받기 전에 보여 줍니다.

**지금 하지 않는 것**
- 이미지·음성 입력, 학습·파인튜닝, 여러 GPU, GGUF가 아닌 형식(safetensors 직접 읽기)
- VRAM보다 큰 모델을 GPU와 CPU에 나눠 돌리기(2차 후보)
- 터미널 명령(`ollama run` 같은 것). API로 대신합니다.
- Code 앱의 AI 자동완성을 이 엔진으로 바꾸는 일(나중 후보)

## 4. 구조

```
메인 프로세스(Node)
  ├─ 모델 저장소: 검색, 받기, 목록, 삭제 (main/mind/models.js)
  ├─ API 서버: 127.0.0.1:11435 (main/mind/api.js)
  └─ 엔진 창 관리: 숨은 창 하나를 띄우고 MessagePort로 요청을 보냄
엔진 창(숨은 렌더러, WebGPU는 렌더러에서만 됨)
  ├─ GGUF 읽기: nano-model:// 프로토콜로 파일을 조각내 받아 텐서별 GPU 버퍼에 씀
  ├─ 토크나이저, 채팅 템플릿
  ├─ 모델 실행(GPU 셰이더, 안 되면 CPU)
  └─ 샘플링, 토큰 스트리밍
화면 창(Mind 모드)
  └─ 채팅, 모델 관리, 설정 (renderer/features/mind/)
```

- 엔진을 따로 숨은 창에 두는 이유: WebGPU는 Node 쪽에 없습니다. 그리고 화면을 닫거나 새로 고쳐도 모델이 메모리에 남아 API가 계속 답할 수 있습니다.
- 모델 파일(1~4GB)은 렌더러 메모리에 통째로 올리지 않습니다. 텐서 단위로 읽어 바로 GPU에 씁니다.
- 포트는 11435를 기본으로 씁니다. Ollama(11434)가 깔려 있어도 부딪치지 않습니다. 127.0.0.1에만 열고, 밖에서 접속하려면 설정에서 직접 켜야 합니다.
- 모델 저장 위치는 `%USERPROFILE%\Nano Studio Models`이고, 설정에서 바꿀 수 있습니다. 테스트는 `PYIDE_MIND_HOME`으로 바꿉니다.

파일 지도(예정)
- `main/mind/gguf.js`: GGUF 헤더와 텐서 목록 읽기(메인과 엔진 둘 다 씀)
- `main/mind/models.js`, `main/mind/hf.js`: 저장소와 Hugging Face
- `main/mind/api.js`: Ollama·OpenAI 호환 라우트
- `renderer/mind-engine/`: 엔진 창(`engine.html`, `gpu.js`, `kernels/*.wgsl`, `model-llama.js`, `tokenizer.js`, `jinja.js`, `sampler.js`, `cpu.js`)
- `renderer/features/mind/`: 화면 플러그인(`"modes": ["mind"]`)
- `verify/mind-*.mjs`: 테스트

## 5. 엔진 설계

**GGUF 읽기.** 버전 3 헤더, 메타데이터 키·값, 텐서 정보(이름, 모양, 형식, 위치)를 읽습니다. 지원하지 않는 구조나 양자화 형식이면 받기 전에 알려 줍니다(검색 결과에 "지원 안 함" 표시).

**양자화 형식(1차).** F32, F16, Q8_0, Q4_K, Q6_K입니다. Q4_K_M 파일은 대부분 Q4_K이고 일부 층이 Q6_K라서 둘 다 필요합니다. 가중치는 양자화된 채로 GPU에 올리고, 셰이더 안에서 블록을 풀면서 곱합니다. 미리 f16으로 풀면 VRAM이 3~4배 들어 4GB에 안 맞습니다.

**연산(셰이더).**
- 행렬·벡터 곱(토큰 하나씩 만들 때): 행 하나를 작업 그룹 하나가 맡고, 블록을 풀면서 vec4로 읽고, 작업 그룹 메모리에서 합칩니다. 2절 실험의 구조를 형식별로 늘린 것입니다.
- 행렬·행렬 곱(프롬프트를 한 번에 넣을 때): 타일 방식.
- RMSNorm, RoPE(모델별 theta와 확장 설정), 어텐션(GQA, 인과 마스크, 문맥이 길면 나눠서 계산), SwiGLU, 잔차 더하기.
- 마지막 로짓에서 온도, top-k, top-p, min-p, 반복 벌점을 적용하고 GPU에서 뽑습니다. 결과 토큰 번호 하나만 CPU로 읽어 옵니다.

**모델 구조.** llama, qwen2(어텐션 바이어스), qwen3(q·k 정규화)부터 합니다. 구조 차이는 표 하나로 둡니다(바이어스 유무, 정규화 위치, RoPE 방식). 구조마다 코드를 복사하지 않습니다.

**KV 캐시.** f16으로 GPU에 둡니다. 크기는 `층 수 x 문맥 길이 x KV 헤드 x 헤드 크기 x 2`입니다. 문맥 길이는 VRAM에 맞춰 자동으로 정하고, 설정에서 바꿀 수 있습니다. 같은 대화를 이어 쓰면 앞부분 캐시를 다시 씁니다.

**토크나이저.** GGUF의 `tokenizer.ggml.model`(gpt2 또는 llama)과 `tokenizer.ggml.pre`로 방식을 고릅니다. 특수 토큰(`<|im_start|>` 같은 것)을 먼저 떼어 내고 나머지를 분리 규칙대로 자릅니다. 한국어와 이모지 같은 여러 바이트 글자가 토큰 경계에서 깨지지 않도록 출력 쪽에서 바이트를 모았다가 내보냅니다.

**채팅 템플릿.** 모델이 가진 Jinja 템플릿을 그대로 실행합니다. for, if, set, 필터 몇 개(`trim`, `tojson` 등), `messages`, `add_generation_prompt`가 필요합니다. 템플릿을 못 읽으면 ChatML로 대신하고 화면에 알립니다.

**Windows GPU 멈춤 대비.** 셰이더 한 번이 2초를 넘으면 Windows가 GPU를 재설정합니다. 긴 프롬프트는 조각으로 나눠 넣고, 장치가 사라지면 모델을 다시 올리고 오류를 알립니다.

**CPU 대체 경로.** 같은 모델 코드를 JavaScript 연산으로 돌립니다. worker 스레드로 나눕니다. 두 가지 쓰임이 있습니다. GPU가 없는 PC에서 작은 모델을 돌리는 것, 그리고 GPU 결과를 검사하는 기준입니다.

**고성능 GPU 고르기.** Mind 모드 프로세스에만 `force_high_performance_gpu`를 켭니다. Code와 Craft에는 영향이 없습니다.

## 6. 모델 받기

- 검색: Hugging Face API에서 GGUF 태그로 찾고 다운로드 수로 정렬합니다. 처음 화면에는 추천 목록(작은 모델부터)을 보여 줍니다.
- 파일 고르기: 저장소 안의 양자화 파일마다 크기, 이 PC에 맞는지(VRAM과 RAM 추정), 지원 여부를 보여 줍니다. 기본 선택은 맞는 것 중 Q4_K_M입니다.
- 받기: 이어받기, 진행률과 속도, 취소, 끝나면 Hugging Face가 준 sha256으로 확인합니다. 다 받기 전에는 `.part` 파일로 둡니다.
- 라이선스: 저장소의 라이선스 태그를 받기 전에 보여 줍니다. 동의가 필요한 모델(gated)은 로그인이 필요해서 1차에서는 "Hugging Face에서 직접 받아 가져오기"로 안내합니다. 앱이 로그인하지 않습니다.
- 가져오기: 이미 가진 `.gguf` 파일을 끌어다 놓아 추가할 수 있습니다.
- 모델별 설정: 이름, 시스템 프롬프트, 온도 등의 기본값, 문맥 길이를 `models.json`에 둡니다. Ollama의 Modelfile 자리입니다.

## 7. API

127.0.0.1:11435에 엽니다. 다른 도구가 Ollama나 OpenAI 주소만 바꿔서 쓸 수 있게 합니다.

- Ollama 호환: `GET /api/tags`, `POST /api/generate`, `POST /api/chat`(스트리밍 NDJSON), `POST /api/show`, `GET /api/ps`
- OpenAI 호환: `GET /v1/models`, `POST /v1/chat/completions`(SSE 스트리밍), `POST /v1/completions`
- 요청이 겹치면 줄을 세웁니다(1차는 한 번에 하나). 다른 모델을 부르면 지금 모델을 내리고 올립니다. 5분 동안 안 쓰면 내립니다(설정 가능).
- `/api/pull`은 2차에서 합니다. 1차는 화면에서 받습니다.

## 8. 화면

- **채팅**: 왼쪽은 대화 목록, 가운데는 채팅입니다. 모델 고르기, 스트리밍, 중지, 다시 만들기, 마크다운과 코드 블록, 대화 저장(로컬 JSON)이 들어갑니다. 아래에 초당 토큰 수와 문맥 사용량을 보여 줍니다.
- **모델**: 내 모델(크기, 양자화, 마지막 사용, 삭제, 설정)과 찾기(검색, 추천, 파일 고르기, 받기 진행)를 나눕니다.
- **설정**: GPU 고르기(자동, GPU, CPU), 저장 위치, API 포트와 외부 접속, 자동으로 내리는 시간을 둡니다.
- 상태 표시줄: 올라간 모델, VRAM 사용, API 켜짐 여부.
- 모든 글은 `tr()`와 `locales/ko.json`을 거칩니다.

## 9. 단계

단계마다 끝나는 기준을 두고, 기준을 통과해야 다음으로 갑니다.

| --- | --- | --- |
| 0. 실험 | GGUF 읽기, Q4_K·Q6_K·Q8_0 행렬·벡터 곱 셰이더, 속도 측정 | 셰이더 결과가 CPU 계산과 오차 1e-3 안에서 같음. 실제 Qwen2.5-1.5B 한 층의 곱 속도를 GB/s로 기록. 목표에 크게 못 미치면 여기서 3번 결정을 다시 여쭙니다. |

| 3. 모드와 저장소 | `--mode=mind`, 시작 화면 카드, 모델 검색·받기·삭제 | 가짜 Hugging Face 서버로 검색, 이어받기, sha256 실패, 취소를 테스트. 실제 받기는 수동 확인만. |
| 4. 화면 | 채팅, 모델, 설정 | 실제 마우스 이벤트로 대화 한 번, 중지, 다시 만들기, 모델 전환. 스크린샷을 보내 드립니다. |
| 5. API | Ollama·OpenAI 호환 라우트 | 공식 `openai` 파이썬 패키지와 `curl`로 스트리밍과 비스트리밍 둘 다 확인. |
| 6. 마무리 | qwen3, 문서(FEATURES, pitfalls, mind-app.md), CI, 릴리스 | CI 통과, 릴리스는 말씀하실 때만. |

## 10. 테스트

- **CI(GPU 없음)**: 테스트 스크립트가 직접 만드는 작은 가짜 모델(층 2개, 무작위 가중치, GGUF)을 씁니다. CPU 경로로 돌리고, 같은 모델을 순수 수식 구현과 비교합니다. GitHub 러너에 WebGPU 대체 장치가 잡히는지는 1단계에서 확인합니다(추정으로는 안 잡힐 가능성이 큽니다).
- **이 PC(GPU)**: 실제 작은 모델을 받아 GPU와 CPU, llama.cpp(테스트 전용) 출력을 비교합니다. `MIND_REAL=1`일 때만 돌아서 CI에는 들어가지 않습니다.
- 받은 모델은 `verify/out/downloads-cache`에 두어 테스트를 정리할 때 지우지 않습니다.
- 다른 테스트처럼 `verify/on-desktop.ps1`로 하나씩 돌립니다.

## 11. 위험

| 위험 | 대응 |
| --- | --- |
| WebGPU 속도가 기대보다 낮음 | 0단계에서 바로 잽니다. 셰이더를 튜닝해도 안 되면 3번 결정(C++/CUDA)을 다시 여쭙니다. |
| K 양자화 블록 구조가 복잡해 틀리기 쉬움 | 형식마다 CPU 풀기 함수와 GPU 셰이더를 같은 테스트 벡터로 비교합니다. |
| 4GB VRAM | 1차 추천 모델은 3B 이하입니다. 화면에서 맞지 않는 파일은 받기 전에 경고합니다. |
| 모델마다 토크나이저 분리 규칙이 다름 | 지원하는 `tokenizer.ggml.pre` 목록을 표로 두고, 없는 값이면 "지원 안 함"으로 막습니다. |
| Jinja 템플릿의 드문 문법 | 인기 모델 템플릿 20개를 테스트 자료로 둡니다. 못 읽으면 ChatML로 대신합니다. |
| 큰 파일 받기 중 끊김 | `.part`와 Range 요청으로 이어받고, sha256이 다르면 지웁니다. |
