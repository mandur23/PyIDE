# 실시간 협업 코딩 계획

Nano Studio Code에서 친구나 팀원이 내 프로젝트에 들어와 같은 파일을 동시에 고치는 기능입니다. VS Code의 Live Share와 비슷합니다. 프로젝트는 호스트의 PC에만 있고, 게스트는 가입 코드로 들어와 호스트의 파일을 보고, 고치고, 실행 결과를 함께 봅니다. 계정이나 우리 서버는 없습니다.

1절의 결정은 모두 추천대로 정했습니다. 0~5단계는 끝났고 6단계(느린 연결 시험, 실제 bore.pub 시험)가 남았습니다. 진행 상황과 남은 일은 9절에 있습니다. 기능의 정확한 동작은 [FEATURES.md](../FEATURES.md)의 "Real-time collaboration (collab)"에 있습니다.

## 1. 정해 주셔야 할 것

| # | 질문 | 추천 | 다른 선택 |
| --- | --- | --- | --- |
| 1 | 누가 파일을 가지나요? | **호스트 중심.** 파일, 저장, 실행, 언어 서버(자동 완성·오류 표시)는 모두 호스트 PC에서 돌고, 게스트는 화면과 편집만 합니다. 게스트 PC에는 아무것도 깔지 않고, 게스트가 받은 사본은 세션이 끝나면 지웁니다. | 각자 사본을 들고 git처럼 맞추는 방식. 오프라인 편집이 되지만 충돌 처리와 실행 환경 맞추기가 훨씬 어렵습니다. |
| 2 | 어떻게 연결하나요? | **bore.pub 터널과 Craft의 비공개 공유 암호화를 그대로 씁니다.** 공유기나 방화벽 설정이 필요 없고, 가입 코드만 있으면 들어옵니다. 터널 회사는 내용을 읽거나 바꿀 수 없습니다. 같은 네트워크(LAN)면 터널 없이 바로 붙는 길도 함께 둡니다. | 우리 중계 서버(운영비와 계정 필요), WebRTC P2P(연결 중개 서버가 필요하고 회사 네트워크에서 자주 막힘) |
| 3 | 동시 편집은 어떤 방식으로 맞추나요? | **이미 있는 OT를 넓힙니다.** 창 여러 개가 한 파일을 함께 고칠 때 쓰는 순서 매기기(호스트가 편집에 번호를 매기고, 늦게 온 편집은 앞의 편집만큼 밀어서 다시 적용)가 이미 동작하고 시험되어 있습니다. 원격 게스트를 "다른 창"처럼 끼워 넣습니다. | CRDT(Yjs 같은 라이브러리). 호스트가 없어도 합칠 수 있지만, 호스트 중심이면 장점이 적고 외부 라이브러리가 늘어납니다. |
| 4 | 게스트의 기본 권한 | **읽기 전용으로 들어오고, 호스트가 사람마다 편집을 켭니다.** | 처음부터 편집 가능 |
| 5 | 실행과 터미널 | **1차는 호스트가 실행하고 출력만 함께 봅니다.** 게스트의 실행 요청은 2차에서 호스트가 매번 허락하는 방식으로 넣습니다. 게스트가 호스트 PC에서 코드를 돌리는 것이라 기본은 꺼 둡니다. | 처음부터 게스트 실행 허용 |
| 6 | 인원 | **호스트 포함 최대 5명** | 더 많이 |
| 7 | 대화 | **1차는 글 채팅만.** 음성·화상은 하지 않습니다. | 음성 포함 |
| 8 | 숨길 파일 | **`.env`, `*.key`, `*.pem`, `.git/`는 기본으로 게스트에게 보이지 않습니다.** 호스트가 목록을 고칠 수 있습니다. | 숨김 없음 |

## 2. 이미 있는 것

새로 만들기보다 지금 있는 조각을 잇는 일이 많습니다.

- **동시 편집 순서 매기기.** `main/windows.js`의 shared documents가 한 파일을 연 창들의 편집에 번호를 매기고, 오래된 번호로 온 편집은 거절합니다. 창(`renderer/core/editors.js`)은 거절된 편집을 못 본 편집만큼 밀어서 다시 보냅니다(`mapPoint`, `survivors`). 줄바꿈 방식(CRLF/LF) 변환, 늦게 합류한 창에 현재 글을 넘기기(`doc:snapshot`), 저장 알림(`doc:saved`)도 있습니다. 지금은 창 사이(IPC)에서만 돌아갑니다.
- **암호화된 친구 연결.** `main/bore-gate.js`가 Craft의 비공개 공유에서 이미 씁니다. 연결마다 X25519 키를 새로 만들고, 가입 코드의 비밀로 서로를 증명하고(HMAC), ChaCha20-Poly1305로 암호화합니다. 녹화해 다시 보내기, 중간에서 바꾸기, 끊어서 정상 종료처럼 보이게 하기를 막고, 아무 소리 없이 소켓만 여는 스캐너가 친구를 막지 못하게 되어 있습니다. `main/bore-client.js`의 `join` 모드와 가입 코드(`nanostudio:join?…`), 붙여 넣기로만 받는 규칙도 있습니다.
- **포트 공유.** `main/features/port-sharing.js`가 IDE에서 띄운 웹 서버나 TCP 서버를 터널로 내보냅니다. 게스트가 호스트의 개발 서버를 브라우저로 보는 데 그대로 씁니다.
- **언어 서버, 실행, 디버거.** 모두 호스트에서 돌고 있으니, 게스트의 요청을 중계만 하면 됩니다.
- **경로 규칙.** `ide.util.pathKey`(대소문자 구분 폴더 포함), 금지된 파일 이름 검사, 임시 파일 후 이름 바꾸기로 하는 저장.

## 3. 구조

```
게스트 Code ── 로컬 리스너 ── bore.pub ── 호스트 Code의 게이트 ── 협업 서버(호스트 main)
                                                                  ├─ 공유 문서(번호 매기기)
                                                                  ├─ 파일 목록과 읽기·저장
                                                                  ├─ 언어 서버 중계
                                                                  └─ 실행 출력, 채팅, 커서
```

- **협업 서버는 호스트의 main 프로세스입니다.** 공유 문서 표(`shared`)의 "문서를 연 쪽"이 지금은 창(webContents)뿐인데, 원격 게스트도 넣습니다. 번호 매기기와 거절 규칙은 그대로 두고, 전달 통로만 IPC에서 네트워크로 바꿉니다. 그래서 창 두 개와 게스트 셋이 한 파일을 고쳐도 순서는 하나입니다.
- **메시지.** 게이트의 암호화된 레코드 위에 JSON 메시지를 보냅니다. 메시지 하나는 레코드 크기(16KB)를 넘으면 나눠 보냅니다. 종류는 다음과 같습니다.
  - 인사와 신원: 이름, 색, 앱 버전
  - 파일 목록과 변화, 파일 열기·닫기
  - 편집(op)과 확인, 스냅샷
  - 커서·선택: 50ms마다 묶어서 보냅니다.
  - 저장 요청, 새 파일·이름 바꾸기·지우기 요청
  - 언어 서버 요청과 응답, 오류 표시
  - 실행 출력, 채팅, 따라가기, 권한 변경, 강퇴
- **게스트에는 디스크가 없습니다.** 게스트의 탭은 `collab://<세션>/<상대 경로>` 문서입니다. 저장을 누르면 호스트에 저장 요청이 가고, 호스트가 지금의 안전한 저장으로 디스크에 씁니다. 게스트가 받은 글은 메모리에만 있고 세션이 끝나면 지웁니다. 복구 백업과 로컬 히스토리도 게스트 쪽에서는 끕니다.
- **경로는 프로젝트 루트 기준 상대 경로만 오갑니다.** 호스트는 `..`, 절대 경로, 드라이브, UNC, 스트림(`:`), 프로젝트 밖으로 나가는 링크를 모두 거절합니다. 숨김 목록(1절 8번)에 걸리는 파일은 목록에도 나오지 않습니다.
- **커서와 이름표.** 다른 사람의 커서와 선택을 그 사람의 색으로 보여 주고, 파일 트리와 탭에 누가 어디를 보는지 점으로 표시합니다. "따라가기"를 켜면 그 사람이 여는 파일과 스크롤을 따라갑니다.
- **실행 취소는 자기 것만 됩니다.** 문서가 공유되면 원격 편집은 Monaco의 실행 취소 기록에 넣지 않고, 창마다 자기 편집의 역연산 기록(`renderer/core/ot.js`의 `newHistory`, `record`, `rebase`, `take`)을 둡니다. 남의 편집이 오면 기록을 그만큼 옮기고, Ctrl+Z는 맨 위의 역연산을 보통 편집처럼 적용해 모두에게 보냅니다. 그래서 Ctrl+Z가 다른 사람이 친 글을 지우지 않습니다. 창 사이 동기화도 같습니다.
- **끊김과 재접속.** 호스트는 문서마다 최근 편집 기록을 보관합니다. 게스트가 다시 붙으면 자기가 본 마지막 번호 이후의 편집만 받고, 기록이 너무 오래됐으면 스냅샷을 받습니다. 끊긴 동안 친 글은 지금의 버퍼 규칙대로 밀어서 다시 보냅니다.
- **언어 서버.** 게스트의 자동 완성, 마우스를 올렸을 때의 설명, 정의로 이동 요청을 호스트의 언어 서버에 그대로 넘기고, 오류 표시는 호스트가 모두에게 보냅니다. 게스트 쪽에는 언어 서버를 띄우지 않습니다.

## 4. 보안

호스트의 PC를 남에게 여는 기능이라, 기본값을 좁게 잡습니다.

- **가입 코드가 유출되면** 그 코드로 들어올 수 있습니다. 그래서 호스트는 새 게스트가 들어올 때마다 "○○님이 들어오려고 합니다"를 보고 수락합니다. 공유를 멈췄다가 다시 시작하면 새 코드가 됩니다.
- **터널 회사(bore.pub)가 엿보거나 바꾸는 것**은 게이트가 막습니다(Craft에서 시험한 그대로).
- **악의적인 게스트에 대한 방어는 다음과 같습니다.**
  - 권한 밖 요청 거절: 읽기 전용 게스트의 편집, 숨김 파일 요청
  - 경로 검사
  - 메시지 크기와 속도 제한
  - 실행은 호스트가 매번 허락할 때만
- **악의적인 호스트에 대한 방어는 다음과 같습니다.**
  - 게스트 쪽에서는 코드를 실행하지 않습니다.
  - 게스트 PC에 파일을 쓰지 않습니다.
  - Markdown 미리 보기 같은 화면은 지금의 sanitizer를 거칩니다.
- **로그.** 세션 기록에는 경로와 이름만 남기고, 파일 내용과 채팅은 남기지 않습니다.

## 5. 단계

각 단계는 테스트로 끝납니다. 단계가 끝날 때마다 보여 드리고 다음으로 갑니다.

| 단계 | 내용 | 확인 |
| --- | --- | --- |
| 0 | 원격 게스트를 공유 문서 표에 넣는 어댑터와 메시지 형식. 네트워크 없이 메모리 안의 가짜 통로 둘로 시험합니다. | Node 시험: 게스트 3명과 창 2개가 무작위 지연 속에서 동시 편집 1만 번. 모두 같은 글로 끝나는지, 자기 실행 취소가 남의 글을 건드리지 않는지 확인; **완료**: `verify/collab-core.mjs` |
| 1 | 협업 시작(가입 코드 복사)과 참여(코드 붙여 넣기), 들어오기 수락, 읽기 전용으로 파일 트리와 파일 보기 | 숨겨진 데스크톱에서 앱 두 개(포트와 사용자 폴더를 따로)를 루프백으로 연결해 시험; **완료**: `verify/collab-join.mjs` |
| 2 | 동시 편집, 커서·선택·이름표, 따라가기, 권한 바꾸기와 강퇴 | 두 앱에서 실제 키 입력으로 동시에 치고 결과 비교; **완료**: `verify/collab-edit.mjs` |
| 3 | 저장, 새 파일·이름 바꾸기·지우기, 끊김과 재접속, 세션 종료 때 게스트 사본 지우기 | 연결을 강제로 끊고 다시 붙여 편집이 하나도 안 사라지는지 확인; **완료**: `verify/collab-files.mjs` |
| 4 | 언어 서버 중계(자동 완성, 설명, 정의로 이동, 오류 표시), 실행 출력 함께 보기, 채팅 | 게스트 쪽 자동 완성이 호스트와 같은 결과인지 확인; **완료**: `verify/collab-lsp.mjs` |
| 5 | 게스트 실행 요청과 호스트 허락, 터미널 함께 보기(쓰기는 허락 후), 웹 서버 포트를 게스트에게 열기 | 허락 없이는 아무것도 실행되지 않는지 확인; **완료**: `verify/collab-run.mjs`, `verify/collab-session.mjs` |
| 6 | 느린 연결 시험(왕복 200ms·500ms, 끊김), 실제 bore.pub 시험, 문서(FEATURES.md, code-app.md, pitfalls.md) | 실제 bore.pub 접속은 공개 터널이 열리므로 하시기 전에 따로 여쭤봅니다 |

## 6. 테스트 방법

- **수렴 퍼즈 시험(Node).** 가짜 통로에 무작위 지연·순서 섞기·끊김을 넣고, 편집을 무작위로 만듭니다(삽입, 삭제, 붙여 넣기, 줄바꿈 변환). 모든 쪽의 글이 같아지는지 봅니다. 지금 창 사이 동기화 시험을 넓힌 것입니다.
- **앱 두 개 시험.** 숨겨진 데스크톱에서 호스트 앱과 게스트 앱을 따로 띄우고(CDP 포트와 사용자 폴더를 다르게) 루프백으로 연결합니다. 테스트용 가짜 bore(Craft 테스트의 대역)에 지연을 넣어 느린 연결도 시험합니다.
- **보안 시험.** 경로 탈출(`..\..\Windows`, `C:\`, `\\server`, `a:b`), 너무 큰 메시지, 읽기 전용 게스트의 편집, 숨김 파일 요청, 녹화한 연결 다시 보내기. 모두 거절되고 호스트에는 아무 일도 없어야 합니다.
- 실제 Microsoft 계정, 실제 공개 터널, 외부 서버는 테스트에서 쓰지 않습니다.

## 7. 하지 않는 것(1차)

- 음성·화상 통화, 계정과 우리 서버
- 호스트가 나가도 이어지는 세션, 오프라인 편집 합치기
- Craft와 Cut의 협업(Cut의 동시 편집은 명령 단위라 따로 설계해야 합니다)
- 게스트 PC에서의 실행과 디버깅

## 8. 위험

- **bore.pub은 제3자 서비스입니다.** 서비스를 거부하면 인터넷 너머 세션이 안 됩니다. 같은 네트워크 직접 연결과 포트 번호 직접 입력을 대안으로 둡니다.
- **지연이 크면 거절과 재전송이 늘어납니다.** 원격 편집은 몇 글자씩 묶어 보내고, 6단계에서 왕복 500ms까지 측정합니다.
- **게스트 문서마다 Monaco 모델이 생겨 메모리가 늘어납니다.** 열린 탭만 모델로 두고, 나머지는 글로만 보관합니다.
- **호스트가 실행을 허락하면 게스트가 호스트 PC에서 코드를 돌립니다.** 허락 대화상자에 무엇을 어디서 실행하는지 그대로 보여 주고, 매번 묻는 것을 기본으로 둡니다.

## 9. 진행 상황

- **실행 취소(0.3.23-beta.2).** Ctrl+Z와 Ctrl+Shift+Z(다시 실행)는 자기 편집만 되돌립니다. 협업과 창 사이 동기화 모두입니다. `verify/ot-undo.mjs`(Node), `verify/collab-edit.mjs`, `verify/multi-window.mjs`가 확인합니다. 문서가 공유되기 전에 한 편집은 이 기록에 없어서, 공유된 뒤에는 되돌릴 수 없습니다.
- **0~5단계 완료.** 앱 두 개를 루프백과 bore.pub 대역(`verify/stand-in-bore.mjs`, 실제 `main/bore-client.js`)으로 연결해 시험합니다. 각 단계의 테스트는 5절 표에 있습니다.
- **처음 계획과 달라진 점.**
  - 게이트 암호화는 bore 클라이언트 프로세스가 아니라 양쪽 main 프로세스에서 돕니다(`main/collab/link.js`). 그래서 같은 네트워크 직접 연결과 bore.pub 연결이 같은 바이트이고, bore 클라이언트는 공개 모드로 바이트만 나릅니다.
  - 끊김과 재접속은 문서별 편집 기록 대신 연결 아래의 세션 층으로 했습니다. 모든 메시지에 번호를 매기고 상대가 받았다고 할 때까지 보관했다가 다시 붙으면 다시 보냅니다. 편집, 저장 요청, 채팅이 모두 한 번씩, 순서대로 갑니다.
  - 손님이 연 파일은 호스트 창에도 뒤쪽 탭으로 열립니다. 호스트의 언어 서버, 문제 표시, 저장을 그대로 쓰기 위해서입니다.
  - 손님의 실행 요청은 "지금 앞에 있는 파일 실행"입니다. 호스트의 실행 구성을 손님이 고르지는 않습니다.
- **남은 일.**
  - 6단계: 느린 연결(왕복 200 ms, 500 ms) 측정. 대역 bore에 지연(`latency`)을 넣는 길은 있습니다.
  - 6단계: 실제 bore.pub 시험. 공개 터널이 열리므로 하기 전에 여쭤봅니다.
  - 손님 쪽에는 "저장 안 함" 표시가 없습니다. 호스트 탭에만 나옵니다.
  - 같은 네트워크 직접 연결은 루프백(`PYIDE_COLLAB_BIND`, `PYIDE_COLLAB_LAN_HOST`)으로만 시험했습니다. 처음 쓸 때 Windows 방화벽이 한 번 물을 수 있습니다.
  - 앱 두 개 테스트는 CI에 넣지 않았습니다. Node 시험(`collab-core`, `collab-session`)만 CI에 있습니다.
