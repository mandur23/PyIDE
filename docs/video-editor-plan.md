# 영상 편집 앱 계획 (검토용 초안)

영상, 음악, 사진을 타임라인에 놓고 자르고 이어 붙여 MP4로 내보내는 앱입니다. 유튜브 영상이나 쇼츠처럼 컷 편집, 자막, 배경음악, 간단한 색 보정을 하는 사람을 첫 사용자로 봅니다. 전문 색 보정, 3D, 다중 카메라 편집은 첫 버전에서 하지 않습니다.

로컬 LLM 앱(Mind)은 보류 중입니다. 계획은 [local-llm-plan.md](local-llm-plan.md)에 그대로 있습니다.

## 1. 정해 주셔야 할 것

| # | 질문 | 추천 | 다른 선택 |
| --- | --- | --- | --- |
| 1 | 어디에 만들까요? | Nano Studio의 새 앱(모드). 시작 화면에 카드가 하나 늘고, 설치 파일, 업데이트, 릴리스, 번역을 그대로 씁니다. | 따로 설치하는 독립 앱 |
| 2 | 앱 이름 | Nano Studio Cut (임시) | 원하시는 이름 |
| 3 | 영상 처리 엔진 | 브라우저 기능으로 직접 만듭니다. 풀기와 압축은 WebCodecs(이 PC의 GPU 하드웨어 사용), 합성과 효과는 WebGPU 셰이더, 소리는 Web Audio입니다. 추가 설치가 없습니다. | FFmpeg 중심. 형식은 거의 다 열리지만 미리보기를 실시간으로 만들기 어렵고, 프로그램을 따로 받아야 합니다. |
| 4 | 이상한 형식(AVI, FLV, 오래된 코덱) | 1차는 MP4, MOV, WebM, MKV만 엽니다. 나머지는 "FFmpeg 받기"를 눌렀을 때만 FFmpeg를 `~/.pyide`에 받아 MP4로 바꿔서 엽니다. | 처음부터 FFmpeg를 설치 파일에 넣기(설치 파일이 80MB쯤 커짐) |
| 5 | 파일 형식 읽기·쓰기(MP4 구조) | 직접 만듭니다. MP4와 WebM 상자 구조를 읽고, MP4를 씁니다. | 오픈소스 라이브러리(mp4box.js, mp4-muxer)를 씀. 빠르지만 "처음부터"가 아님 |

## 2. 이 PC에서 확인한 것

Electron 45로 짧게 실험했습니다. 실험 파일은 지웠습니다.

| 코덱 | 풀기(하드웨어) | 압축(하드웨어) | 압축(소프트웨어) |
| --- | --- | --- | --- |
| H.264 | 됨 | 됨 | 됨 |
| HEVC(H.265, 아이폰 영상) | 됨 | 됨 | 안 됨 |
| VP9 | 됨 | 안 됨 | 됨 |
| AV1 | 안 됨(소프트웨어로는 됨) | 안 됨 | 됨 |

- 소리 압축은 AAC와 Opus 둘 다 됩니다.
- WebGPU는 GTX 1650이 잡힙니다(`force_high_performance_gpu`를 켰을 때).
- FFmpeg는 이 PC에 없습니다.
- 정리하면, 1080p H.264로 미리보기하고 내보내는 데 필요한 것은 이 PC에 다 있습니다. 내보내기 기본은 H.264와 AAC를 넣은 MP4입니다. 거의 모든 곳에서 재생됩니다.

## 3. 첫 버전 기능

기능별 상세 설계는 [video-editor-features.md](video-editor-features.md)에 있습니다. 아래는 요약입니다.

**가져오기와 정리**
- 영상, 음악, 사진을 끌어다 놓거나 파일 대화상자로 가져옵니다.
- 미디어 칸에 썸네일, 길이, 해상도를 보여 줍니다.
- 원본 파일은 바꾸지 않습니다. 프로젝트는 원본의 경로만 기억합니다.

**타임라인**
- 영상 트랙 여러 개(위가 앞에 보임), 오디오 트랙 여러 개, 텍스트 트랙이 있습니다.
- 클립 놓기, 옮기기, 양 끝 끌어 자르기, 재생 위치에서 나누기(S), 지우기, 빈 곳 메우며 지우기(Shift+Delete)가 됩니다.
- 클립 끝, 재생 위치, 마커에 붙습니다(스냅). 트랙 잠그기, 숨기기, 소리 끄기도 있습니다.
- 확대·축소, 영상 썸네일 띠, 소리 파형이 보입니다.
- 실행 취소와 다시 실행은 끝없이 됩니다. 자동 저장과 복구도 있습니다.

**미리보기**
- 재생, 멈춤, 한 프레임씩 이동이 됩니다. J/K/L 키와 Space를 씁니다.
- 화면 비율은 16:9, 9:16(쇼츠), 1:1, 4:5 중에서 고릅니다.
- 미리보기 화질은 전체, 1/2, 1/4 중에서 고릅니다. 무거운 영상은 편집용 저화질 사본(프록시)을 만들어 씁니다.

**클립 속성(오른쪽 칸)**
- 위치, 크기, 회전, 자르기(크롭), 불투명도
- 밝기, 대비, 채도, 색온도
- 속도(0.25배~4배, 소리 높낮이 유지), 거꾸로 재생
- 볼륨, 소리 페이드 인·아웃
- 전환: 크로스 디졸브, 검은 화면으로 페이드, 밀기

**텍스트와 자막**
- 제목 텍스트를 넣고 글꼴, 크기, 색, 외곽선, 배경 상자, 위치를 정합니다.
- 자막은 SRT로 가져오고 내보냅니다. 자막 목록 칸에서 시간과 글을 고칩니다.

**내보내기**
- 기본은 MP4(H.264, AAC)입니다. 프리셋은 유튜브 1080p, 쇼츠 1080x1920, 720p, 4K(이 PC에서 되는 경우)입니다.
- 화질(비트레이트), 프레임 수(24, 30, 60)를 고르고, 구간만 내보낼 수 있습니다.
- 진행률, 남은 시간, 취소를 보여 줍니다. GPU 하드웨어 압축을 쓰고, 안 되면 소프트웨어로 합니다.
- 소리만 내보내기(M4A)와 지금 화면을 PNG로 저장하기도 됩니다.

**2차 후보(지금 하지 않음)**
- 키프레임 애니메이션, 크로마키, LUT, 오디오 효과(잡음 제거, 음량 맞추기)
- 화면 녹화, 자동 자막(Mind 앱의 음성 인식과 연결)
- 템플릿, GIF 내보내기, HDR과 10비트

## 4. 구조

```
메인 프로세스(Node)
  ├─ 프로젝트 파일(.ncut, JSON) 읽기·쓰기, 자동 저장, 복구
  ├─ 미디어 파일 읽기: nano-media:// 프로토콜로 원하는 구간만(Range) 넘겨줌
  ├─ 캐시: 썸네일, 파형, 프록시 (%LOCALAPPDATA%\Nano Studio\cut-cache)
  └─ FFmpeg(선택): 받기, 이상한 형식을 MP4로 바꾸기
렌더러(Cut 모드 창)
  ├─ 타임라인 모델과 편집 명령(실행 취소 기록)
  ├─ 화면: 미디어 칸, 미리보기, 속성 칸, 타임라인
  └─ 미리보기 엔진
       ├─ 컨테이너 읽기: MP4/MOV, WebM/MKV (직접 만듦)
       ├─ 풀기: WebCodecs VideoDecoder, AudioDecoder
       ├─ 합성: WebGPU (트랙 겹치기, 변형, 색, 전환, 텍스트)
       └─ 소리: Web Audio (섞기, 볼륨, 속도)
내보내기 작업(같은 엔진을 실시간이 아니라 프레임 단위로)
  └─ 합성 → VideoEncoder/AudioEncoder → MP4 쓰기(직접 만듦) → 파일
```

- 미리보기와 내보내기는 같은 합성 코드를 씁니다. 그래서 미리보기에서 본 것과 결과 파일이 같습니다.
- 영상 파일은 통째로 메모리에 올리지 않습니다. 필요한 구간만 읽습니다.

파일 지도(예정)
- `main/cut/project.js`, `main/cut/media.js`, `main/cut/cache.js`, `main/cut/ffmpeg.js`
- `renderer/features/cut/`: 화면 플러그인(`"modes": ["cut"]`)
- `renderer/cut-engine/`: `mp4-read.js`, `mkv-read.js`, `mp4-write.js`, `decoder.js`, `compositor.js`, `shaders/*.wgsl`, `audio.js`, `export.js`
- `renderer/cut-engine/timeline.js`: 데이터 모델과 편집 명령
- `verify/cut-*.mjs`: 테스트

## 5. 핵심 설계

**데이터 모델.** 프로젝트에는 설정(해상도, 프레임 수, 표본율), 미디어 목록, 트랙 목록이 있습니다. 클립은 `{id, media, 원본 시작, 원본 끝, 타임라인 시작, 속도, 속성, 효과}`입니다. 시간은 소수 대신 정수 틱(1/120000초)으로 저장합니다. 소수로 더하고 빼면 오차가 쌓여 프레임이 한 칸씩 어긋나기 때문입니다. 24, 25, 30, 29.97, 60fps가 모두 정수 틱으로 떨어집니다.

**편집 명령.** 모든 편집은 명령 하나입니다(나누기, 옮기기, 자르기, 속성 바꾸기). 명령은 실행과 되돌리기를 둘 다 가집니다. 그래서 실행 취소, 자동 저장, 테스트가 같은 길을 씁니다.

**미리보기.** 재생 위치의 프레임을 트랙마다 구해서 겹칩니다.
- 영상은 키프레임에서부터 풀어야 해서, 앞으로 갈 프레임을 미리 풀어 둡니다(프레임 캐시).
- 뒤로 가거나 멀리 뛸 때는 가까운 키프레임으로 갑니다.
- 키프레임 간격이 긴 영상(휴대폰 영상)은 자동으로 프록시를 권합니다.
- 다 쓴 `VideoFrame`은 바로 닫습니다. 안 닫으면 GPU 메모리가 새서 몇 분 뒤에 멈춥니다.

**소리.** 미리보기는 Web Audio로 섞고, 소리 시계를 기준으로 영상을 맞춥니다(입 모양 맞추기). 내보내기는 같은 그래프를 오프라인으로 돌립니다.

**가변 프레임 영상.** 휴대폰 영상은 프레임 간격이 일정하지 않습니다. 각 프레임의 실제 시간표를 읽어서 씁니다. 프레임 번호로 계산하지 않습니다.

**내보내기.** 프레임마다 합성 → `VideoFrame` → 압축 → MP4에 씁니다. 압축기가 밀리면 기다립니다(대기열이 넘치지 않게). 끝나면 만든 파일을 다시 열어 길이와 첫·끝 프레임을 확인합니다.

## 8. 테스트

- **시험 영상은 테스트가 직접 만듭니다.** 각 프레임에 프레임 번호를 큰 숫자와 색 칸으로 그리고, 1초마다 삐 소리와 흰 화면을 넣습니다. 그래서 "3.5초에 보이는 프레임이 105번인가", "소리와 화면이 같이 나오는가"를 정확히 검사할 수 있습니다. 저작권 있는 영상은 쓰지 않습니다.
- **CI**: GitHub 러너에는 GPU가 없습니다. 소프트웨어 H.264 압축과 풀기는 Chromium에 있어서 CI에서도 돕니다(이 PC에서 소프트웨어 압축이 되는 것은 확인했고, 러너에서 되는지는 0단계에서 확인합니다). WebGPU가 안 잡히면 같은 합성을 Canvas 2D로 하는 대체 경로로 검사합니다.
- **이 PC**: 하드웨어 압축과 HEVC 풀기, 4K 재생 속도를 `CUT_REAL=1`일 때만 검사합니다.
- 다른 테스트처럼 `verify/on-desktop.ps1`로 하나씩 돌리고, 끝나면 정리합니다.

## 9. 위험

| 위험 | 대응 |
| --- | --- |
| 휴대폰 영상의 긴 키프레임 간격 때문에 앞뒤로 움직일 때 느림 | 프레임 캐시와 프록시. 0단계에서 실제 휴대폰 영상으로 잽니다. |
| 가변 프레임 영상의 소리·영상 어긋남 | 프레임마다 실제 시간을 씀. 2단계 기준에 넣었습니다. |
| `VideoFrame`을 안 닫아서 GPU 메모리가 샘 | 프레임을 빌리고 돌려주는 한 곳만 두고, 테스트에서 열린 프레임 수가 0으로 돌아오는지 셉니다. |
| HEVC 소프트웨어 압축이 없음 | 내보내기는 H.264가 기본입니다. HEVC는 하드웨어가 있을 때만 고를 수 있게 합니다. |
| MP4 쓰기를 틀리면 일부 플레이어에서 안 열림 | 결과를 우리 읽기 코드와 Windows 미디어 플레이어, 브라우저 `<video>`에서 둘 다 엽니다. |
| 10비트, HDR 영상 | 1차는 8비트로 바꿔서 열고 "HDR은 아직 지원 안 함"을 알립니다. |
