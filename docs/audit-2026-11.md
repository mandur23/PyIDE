# 문제점 조사 (2026-11-10, 0.3.25 기준)

Code, Craft, Cut과 보안 영역을 코드로 읽어 찾은 41건 중 40건을 0.3.26과 0.3.27에서 고쳤습니다. 고친 내용은 `CHANGELOG.md`에, 남은 규칙은 `pitfalls.md`에 있습니다. 아래는 아직 남은 것입니다.

## 남은 것

- **렌더러를 `file://`에서 전용 스킴으로 옮기기(보안 3번의 나머지).** UI가 `file://`이라 CSP의 `'self'`가 로컬 파일 전체를 뜻합니다. IPC는 이제 앱 페이지의 맨 위 프레임만 받으므로(`main/ipc-guard.js`), 남은 이득은 주입 지점이 생겼을 때 `<script src=file:...>`가 실행되지 않는 것입니다. 옮기려면 창 로드, preload와 guard의 페이지 판정, 플러그인 스크립트 로드(`main/plugin-manager.js:331`), Monaco 워커, 로컬 이미지와 Cut 미디어의 file: 주소, HTML 미리 보기 프레임, `location.pathname`을 보는 테스트를 모두 바꿔야 합니다. 위험도 높음, 2~4일과 전체 CI.
- **앱 전체의 단일 인스턴스 잠금은 넣지 않았습니다.** Craft는 서버 폴더의 실행 표시로, Cut은 저장 전 mtime 비교로 막습니다. 신뢰 목록과 `cut-control.json`은 두 인스턴스가 여전히 같이 씁니다(외부 AI는 나중에 뜬 인스턴스에 닿습니다).
- **실제 환경으로만 확인할 수 있는 것.** Windows 종료 때 서버 정지(`query-session-end`), 설치본에서 업데이트 재시작 전 서버 정지, 설치본의 `--pyide-test-env` 경로(`verify/installed.mjs`), GitHub에서 MSI 내려받기.
- **Craft:** `detectServer`가 `META-INF/versions.list`가 있는 jar를 모두 Paper로 봅니다. Mojang의 1.18 이후 server.jar와 Spigot도 같은 구조라 Paper로 잘못 표시될 수 있습니다(추정, 실제 jar로 확인하지 않음).
- **Code:** LSP 이름 바꾸기(`renderer/features/lsp/index.js:595`)도 여러 파일을 되돌리기 없이 씁니다. 다시 실행(Rerun on Save), 자동 테스트, 파일 감시는 협업 게스트의 저장으로도 실행됩니다(호스트가 켠 기능).

## 기능 공백과 프로젝트 전반

- Craft는 서버 jar를 UI에서 업데이트할 수 없고, 비공개 공유 코드가 서버를 다시 시작할 때마다 바뀝니다. 월드 백업과 이상 종료·과부하 처리는 0.3.29에 들어갔지만 실제 마인크래프트 서버로는 확인하지 못했습니다.
- Cut은 클립마다 디코더를 따로 열어 점프 컷이 많은 타임라인이 느리고, 그래픽 레이어를 손으로 편집하는 패널이 없습니다.
- CI가 불안정합니다(시간 초과로 한 번 실패했다가 재실행에서 통과하는 테스트가 릴리스마다 하나씩 나옴). 코드 서명이 없습니다. 린트나 타입 검사가 없습니다. `dist/`가 11GB를 넘습니다.
