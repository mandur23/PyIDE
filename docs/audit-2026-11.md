# 문제점 조사 (2026-11-10, 0.3.25 기준)

Code, Craft, Cut과 보안 영역을 코드로 읽어 찾은 문제입니다. 아직 고친 것은 없습니다. 고치면 해당 줄을 지우고, 규칙이 남으면 `pitfalls.md`에 적습니다.

확인 수준은 세 가지로 적었습니다.

- **재현**: 실제 앱이나 스크립트로 문제를 일으켜 봤습니다.
- **코드 확인**: 코드 경로를 끝까지 읽었지만 실행해 보지는 않았습니다.
- **추정**: 일부만 확인했고 실제 결과는 시험하지 않았습니다.

0.3.26에서 고친 것: Code 1·2번, Cut 1·2·3번, Craft 1번, 보안 1·2번(아래 목록에서 지웠습니다. 번호는 처음 조사 때의 것입니다).

## Code

3. **플러그인이 UTF-8이 아닌 파일을 깨뜨림 (중, 코드 확인. 조사자가 node로 재현).** `fs:read`/`fs:write`는 항상 UTF-8로 읽고 씁니다. PowerShell 5가 만든 UTF-16 `requirements.txt`나 `.gitignore`, CP949 파일에 줄을 추가하면 내용이 깨집니다. 위치: `main.js:240-246`, 호출부는 requirements-sync, packages, exe-builder, http-client. 수정: `textCodec`으로 읽고 쓰며 인코딩을 유지합니다.
4. **리팩터링이 중간에 실패하면 반쯤 바뀐 채 남음 (중, 코드 확인).** 파일을 하나씩 쓰고 실행 취소 기록은 맨 끝에만 남깁니다. 위치: `renderer/features/refactor/index.js:413-437`. 수정: 실패하면 그때까지 모은 기록으로 되돌립니다.
5. **IDE 다시 시작에서 취소해도 세션이 망가짐 (중, 코드 확인).** `before-quit`에서 터미널, DB 연결, 로컬 히스토리 감시가 먼저 정리된 뒤에 저장 확인 대화상자가 뜹니다. 취소해도 이미 끝난 것은 돌아오지 않습니다. 위치: `main.js:502-506`. 수정: 확인을 먼저 받고, 정리는 `will-quit`으로 옮깁니다.
6. **렌더러가 죽거나 멈추면 창을 닫을 수 없음 (중, 코드 확인).** 저장 안 한 파일이 있으면 닫기를 막고 응답 없는 페이지에 확인을 보냅니다. 위치: `main/windows.js:49-56`. 수정: 응답이 없으면 네이티브 대화상자를 띄웁니다.
7. **탭 한도(기본 10)가 상태를 가진 탭을 말없이 닫음 (중하, 코드 확인).** 커널이 살아 있는 노트북이나 해결 중인 병합 탭이 대상이 됩니다. 위치: `renderer/core/editors.js:497-505`.
8. **Git 롤백의 다시 읽기가 문서 인코딩을 무시함 (낮음).** `renderer/features/vcs/index.js:97`.
9. **신뢰 목록과 프로젝트 루트 저장소가 읽기 실패 뒤 빈 목록으로 덮어써짐 (낮음, 코드 확인).** `main/trust.js:14-33`, `main/project-roots.js:27-51`.
10. **노트북을 닫을 때 마지막 300ms의 입력이 저장되지 않음 (낮음, 코드 확인).** `renderer/features/notebook/index.js:1552-1554`. `disposed`를 세운 뒤 `flush()`를 부릅니다.
11. **Kotlin 언어 서버를 cmd.exe로 띄워 JVM이 남을 수 있음 (낮음, 추정).** `main/lsp-server.js:386-394`.

## Craft

2. **실행 상태가 렌더러에만 있음 (중상, 코드 확인).** 메인에 폴더별 실행 잠금이 없고, 앱보다 오래 산 서버를 알아보지 못합니다. 앱 전체의 단일 인스턴스 잠금도 없습니다. 위치: `main/features/minecraft.js:536-537`, `:611-630`. 수정: 서버 폴더에 pid 파일을 두고, 살아 있으면 시작을 거절하고 종료 버튼을 보여 줍니다.
3. **공개 터널이 앱이 죽어도 남음 (중, 코드 확인).** `followParent()`를 비밀 키가 있을 때만 부릅니다. 공개 공유의 bore 클라이언트는 앱이 죽어도 계속 중계합니다. 위치: `main/bore-client.js:186-187`. 수정: 조건 없이 부릅니다.
4. **Windows 종료나 로그오프 때 서버에 `stop`을 보내지 않음 (중, 추정).** `session-end` 처리가 없습니다. 위치: `main.js:644-699`.
5. **멈춤이 60초 뒤 무조건 강제 종료 (중, 코드 확인).** 큰 모드팩은 저장 중에 죽을 수 있고, 강제 종료했다는 표시도 없습니다. 위치: `renderer/features/minecraft/index.js:58`, `:89-97`. 수정: 출력이 60초 없을 때로 바꾸고 강제 종료를 알립니다.
6. **클라이언트 팩 만들기가 메인 프로세스를 멈춤 (중하, 코드 확인).** 모든 모드를 동기로 압축하고, 참여 코드 복사 때마다 다시 만듭니다. 4GB나 65,535개를 넘으면 오류 없이 깨진 zip이 됩니다. 위치: `main/minecraft/zipfile.js:16-41`.
7. **실행 중 저장한 설정이 서버의 `server.properties` 다시 쓰기로 사라짐 (중하, 코드 확인).** 앱이 보낸 `whitelist on`만 보호합니다. 위치: `main/features/minecraft.js:647-669`.
8. **online-mode를 바꾸면 화이트리스트와 관리자 UUID가 맞지 않게 됨 (중하, 코드 확인).** 경고가 없습니다. 위치: `renderer/features/minecraft/server-settings.js:444`, `:490`.
9. **Paper 월드를 끌어 놓으면 차원 폴더를 각각 다른 월드로 취급 (중하, 코드 확인).** `main/minecraft/imports.js:85`, `:239-245`.
10. **Mojang 버전 목록을 앱이 켜져 있는 동안 계속 캐시 (중하, 코드 확인).** `main/minecraft/sources.js:102-110`.
11. **`pyide-server.json`을 제자리에 쓰고, 깨지면 고칠 방법이 없음 (낮음, 코드 확인).** `main/features/minecraft.js:39`, `:496`.
12. **가져온 Velocity 프록시가 online-mode=false여도 공유 경고가 없음 (낮음, 코드 확인).** `main/features/minecraft.js:340-357`.

기능 공백: 월드 백업이 없습니다. 서버 jar를 UI에서 업데이트할 수 없습니다. 비공개 공유 코드는 서버를 다시 시작할 때마다 바뀝니다.

## Cut

4. **자동 저장 사본을 열어 그대로 저장하면 나중에 앱이 지움 (중, 코드 확인).** 30일 정리와 20개 회전이 파일 이름으로만 판단합니다. 자동 저장 목록을 보여 주는 UI도 없습니다. 위치: `main/cut/project.js:231-237`, `ui-shell.js:505-515`.
5. **프로젝트 저장에 fsync와 이전 파일 백업이 없음 (중, 추정).** 저장 직후 정전이면 빈 파일이 남을 수 있습니다. 위치: `main/cut/project.js:37-46`.
6. **쓰기 실패가 내보내기를 멈추지 않고, 인코더 대기가 취소를 보지 않음 (중, 코드 확인. 조사자가 node로 재현).** 디스크가 20%에서 가득 차도 100%까지 렌더링한 뒤에야 실패합니다. 위치: `mp4write.js:83-85`, `export.js:642-655`, `:671`.
7. **faststart 실패가 내보내기 실패로 보고됨 (중하, 코드 확인).** 파일은 완성돼 있습니다. 디스크가 두 배 필요하고 임시 파일이 남을 수 있습니다. 위치: `main/cut/faststart.js:172-194`.
8. **프록시 작업이 끝나면 다시 실행 기록이 지워짐 (중하, 재현은 조사자).** 프록시 연결이 실행 취소 단계로 들어갑니다. 위치: `ui-proxy.js:119-126`.
9. **프로젝트를 바꿔도 AI 턴이 계속 편집함 (중하, 코드 확인).** 남은 도구 호출이 새 프로젝트에 적용됩니다. 위치: `ui-assistant.js:89-110`.
10. **저장 중에 한 편집이 저장된 것으로 표시됨 (낮음, 재현은 조사자).** `ui-shell.js:522-530`.
11. **미디어 다시 연결이 파일 내용을 확인하지 않음 (중하, 코드 확인).** 다른 파일이나 더 짧은 파일을 받아들입니다. 위치: `ui-project.js:223-232`.
12. **앱을 두 번 띄워 같은 프로젝트를 열면 서로 덮어씀 (중하, 추정).** 단일 인스턴스 잠금이 없고 mtime을 비교하지 않습니다.

설계 약점: 클립마다 디코더를 따로 열어 점프 컷이 많은 타임라인이 느립니다. 그래픽 클립의 레이어를 손으로 편집하는 패널이 없습니다.

## 보안

치명적인 문제나 인증 없이 원격에서 코드를 실행할 경로는 찾지 못했습니다.

3. **렌더러 구조 (중, 심층 방어).** `ide.api.invoke`가 모든 채널을 통과시키고 핸들러가 보낸 쪽을 확인하지 않습니다. UI가 `file://`이라 CSP의 `'self'`가 로컬 파일 전체를 뜻합니다. 지금은 주입 지점을 찾지 못했지만, 하나라도 생기면 전체 권한이 됩니다. 위치: `preload.js:22-25`, `renderer/index.html:5`.
4. **안전 모드의 "기본 앱으로 열기" 차단 목록에 `.pyc`, `.pyzw`, `.chm`, `.sh` 등이 빠짐 (낮음, 조사자가 node로 확인).** `main/trust.js:50-51`.
5. **테스트용 환경 변수가 설치본에서도 동작 (낮음, 코드 확인).** `PYIDE_TRUST_ALL`, `PYIDE_RELEASE_PUBLIC_KEY`, `PYIDE_UPDATE_FEED` 등. 수정: 패키지된 빌드에서는 읽지 않습니다.
6. **마크다운 미리 보기가 안전 모드에서도 원격 이미지를 불러옴 (낮음, 코드 확인).** `renderer/features/viewers/index.js:1018-1024`.

## 프로젝트 전반

- **CI 신뢰도.** 최근 40회 실행 중 성공 10, 실패 19, 취소 11입니다. 0.3.24와 0.3.25 이틀 사이에 서로 다른 테스트 세 개(`exe-builder`, `rename-module`, `vcs-log-actions`)가 시간 초과로 한 번씩 실패했다가 다시 돌리면 통과했습니다. 빨간 결과를 재실행으로 넘기는 일이 습관이 되면 진짜 실패를 놓칩니다.
- **테스트가 키 입력의 실제 경로를 못 봄.** CDP로 보낸 키는 메뉴 단축키를 건너뜁니다. Ctrl+R 문제가 289개 스위트를 통과한 이유입니다.
- **코드 서명 없음.** 설치할 때 SmartScreen 경고가 뜹니다.
- **README와 package.json 설명이 "두 가지 앱"으로 남아 있음.** Cut이 빠져 있습니다.
- **`dist/`가 11GB(파일 149개).** 지우지 않는 규칙이라 계속 늘어납니다.
- **린트나 타입 검사 없음.** 앱 코드 15만 줄에 정적 검사가 없고, 검증은 전부 앱을 띄우는 테스트에 의존합니다.
